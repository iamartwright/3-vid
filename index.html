🎞️ GitHub 视频仓方案

在 GitHub 里“存很多视频”的正确架构（含可运行 Demo）

1. GitHub 的硬限制（先别踩坑）

项目限制说明
单文件 push100 MB超过直接拒绝 [1](@ref)
网页端上传25 MB大文件用命令行
仓库体积建议 <1GB超 5GB GitHub 会找你 [1,4](@ref)
Git LFS 免费1GB 存储+1GB/月流量超了买 Data Pack [1,3](@ref)
Release 附件单文件 2GB不计入仓库体积 [1](@ref)

⚠️ 不要把几十个 200MB 的 mp4 直接 git add，仓库会炸。

2. 视频仓的四种存法（按场景选）

A. 小视频（<25MB）

直接放仓库 videos/，GitHub Pages 直链播放。

B. 中视频（25–100MB）

命令行 push 进仓库，或挂 Release 附件。

C. 大视频（>100MB）

用 Git LFS 或丢 Release，代码仓只留指针/链接。

D. 很多大视频 / 要流畅播

FFmpeg 切 HLS（m3u8+ts）→ 放仓库 → jsDelivr CDN 加速。

3. 方案 A：小视频直放（GitHub Pages 直链）

目录结构：

video-warehouse/
├── index.html
└── videos/
    └── demo.mp4   （<25MB）

HTML 里直接引相对路径：

<video src="videos/demo.mp4" controls></video>

✅ 打开 https://你的名.github.io/video-warehouse/ 就能播

4. 方案 D：HLS 切片 + jsDelivr（推荐做“视频仓”）

① 用 FFmpeg 把 mp4 切成 HLS：

ffmpeg -i in.mp4 -c:v h264 -c:a aac \
  -hls_time 10 -hls_list_size 0 \
  -f hls videos/hls/playlist.m3u8

② 推到公开仓库，用 jsDelivr 拿 CDN 地址：

https://cdn.jsdelivr.net/gh/用户名/仓库名@main/videos/hls/playlist.m3u8

jsDelivr 只加速公开仓库，私有仓不行 [2,5](@ref)

③ 网页里用 hls.js 播（非 Safari 也能播）：

<video id="v" controls></video>
<script src="https://cdn.jsdelivr.net/npm/hls.js@1"></script>
<script>
const src="https://cdn.jsdelivr.net/gh/用户名/仓库名@main/videos/hls/playlist.m3u8";
const v=document.getElementById("v");
if(Hls.isSupported()){const h=new Hls();h.loadSource(src);h.attachMedia(v);}
else if(v.canPlayType("application/vnd.apple.mpegurl")){v.src=src;}
</script>

5. Git LFS 最小配置（大文件不撑爆仓库）

# 安装一次
git lfs install

# 跟踪视频
git lfs track "*.mp4"
git add .gitattributes

git add videos/big.mp4
git commit -m "add big video via LFS"
git push origin main

⚠️ 所有协作者都要装 git-lfs，否则拉到的是指针文件 [8](@ref)

6. 视频仓推荐目录（可直接抄）

video-warehouse/
├── index.html
├── videos/
│   ├── small/        # <25MB 直放
│   ├── lfs/          # 大文件走 Git LFS
│   └── hls/          # m3u8 + ts 切片
├── releases.md       # 超大文件走 GitHub Release
└── README.md

7. 一句话选型

少量小视频 → 直接放仓库
几个百兆视频 → Git LFS / Release
视频仓 + 网页播放 → HLS 切片 + jsDelivr
商业/超大流量 → S3 / R2 / 阿里云 OSS + CDN
